# 持股管理頁面作業須知與功能設計規範 (Holdings)

- **路由端點**：`/holdings`
- **頁面檔案**：`app/pages/holdings.vue`
- **當前狀態**：功能骨架殼（顯示「功能開發中，敬請期待」），navbar 項目已於 2026-09-04 啟用。
- **未來狀態管理**：規劃建立 `app/composables/holdings/useHoldings.ts`。

---

## 1. 核心定位與本質邊界 (與「觀察清單」之嚴格劃分)

前端工程師在實作持股管理時，切勿將其與「觀察清單（Watchlist）」混淆：
- **觀察清單 (Watchlist)**：純追蹤清單，使用者**並未實際持有**，不需要填寫買入成本與股數。
- **持股管理 (Holdings)**：使用者**真金白銀實際持有**之資產。核心任務是進行「成本損益統計」、「年度稅後現金流試算」與「三水桶動態資產配置分艙」。

---

## 2. 功能架構與核心業務邏輯規範

未來串接資料模型與實作 UI 時，需依據退休金融知識庫實作以下三大子系統：

### 子系統一：三水桶資產配置分艙儀表 (Bucket Allocation)
- **理論對齊**：依據 [[三水桶資產配置策略 (Three-Bucket Strategy)]]，系統將使用者輸入的持股歸納至三大生活功用艙：
  - **第 1 水桶（短期流動金）**：定存、貨幣市場、短期公債（目標佔比 10%–15%，支應 1–3 年生活費）。
  - **第 2 水桶（中期收益艙）**：中天期債券 ETF、官股金融股（目標佔比 45%–55%，支應 4–8 年支出）。
  - **第 3 水桶（長期抗通膨成長艙）**：0050、006208、VTI、低波高息股票（目標佔比 30%–40%）。
- **合規防火牆**：
  - 嚴格遵守 [[Robo-Advisor 自動化投顧法規紅線]]，系統**僅能呈現當前比例與目標比例之偏離度**（如「第 3 水桶目前超標 8%」）。
  - **嚴禁自動下單調倉，嚴禁直接推介個別有價證券買賣**。

### 子系統二：稅後實質現金流日曆與健保試算 (Tax-Smart Cashflow)
- **實質現金流拆解**：
  - 依據 [[台灣證券稅制與所得分離最佳化]]，當使用者輸入持股後，系統依各檔標的歷史配息通知書成分，自動拆解為「54C 境內股利」、「已實現資本利得（76）」、「收益平準金」與「海外所得（71）」。
- **二代健保 2.11% 自動預扣計算**：
  - 針對各單次配息事件，若其「54C 股利金額 $\ge 20,000$ 元」，系統自動扣除 2.11% 補充保費，於現金流日曆上直接呈現**「實質到手手取現金（After-Tax Net Cash）」**，並以醒目標籤標記 `已預扣二代健保 $XXX 元`。
- **總報酬提領輔助**：
  - 依據 [[總報酬提領 vs 高股息現金流]]，提供「資本利得自行賣股換生活費」之試算功能，展示證券交易所得免稅相較於純領息的節稅效益。

### 子系統三：動態提領安全護欄監控 (Dynamic Guardrails)
- **理論對齊**：依據 [[Guyton-Klinger 動態提領護欄模型]]，根據使用者設定的年度基本生活費預算與當前持股總市值，即時計算當期提領率：
  - **資本保全警告（下限護欄）**：若因市場下跌使提領率上升超過期初基準 20%，系統溫和提示：「觸發資本保全護欄，建議本季生活費支出微幅縮減 10%」。
  - **繁榮分享通知（上限護欄）**：若因大牛市使提領率下降超過期初基準 20%，提示：「投資組合表現優異，可適度提高 10% 提領額度」。

## 3. 前端資料模型設計指引 (Data Schema Proposal)

在 `app/composables/holdings/useHoldings.ts` 中規劃之持股資料結構應涵蓋：

```typescript
export interface HoldingPosition {
  id: string;
  stockCode: string;          // 股票代碼 (如 '2330')
  stockName: string;          // 股票名稱 (如 '台積電')
  shares: number;             // 持有股數 (可支援零股)
  costBasisPerShare: number;  // 每股平均買進成本
  bucketId: 1 | 2 | 3;        // 所屬水桶分艙 (1:短期流動, 2:中期現金流, 3:長期成長)
  customNotes?: string;       // 使用者自訂備註
}

export interface HoldingSummary {
  totalMarketValue: number;   // 總持股市值
  totalUnrealizedPnL: number; // 未實現總損益
  totalEstimatedYieldAnnual: number; // 預估年度總股息
  estimatedAfterTaxCashflow: number; // 扣除健保費後預估淨現金流
  currentWithdrawalRate: number;     // 當前動態提領率
}
```

## 4. UI/UX 與無障礙工程約束

- **表格與卡片雙軌視圖**：桌機採用滿版 RWD 表格（`HoldingsTable.vue`），手機版（$< 768\text{px}$）自動折疊為多維卡片流（`HoldingsCard.vue`）。
- **360px 零破版保證**：手機持股卡片在 360px 視窗下，損益、股數、現價採用三欄網格緊湊排列，文字嚴格遵守 $\ge 16\text{px}$ 下限。詳見 [[高齡友善排版與觸控熱區規範]]。
- **色彩多維冗餘**：損益欄位禁止純靠紅綠，必須配置顯式符號前綴（`+` / `-`）與箭頭（▲ / ▼）。詳見 [[多維視覺冗餘編碼 (Visual Redundancy)]]。
- **手勢與防誤觸**：刪除或清空持股操作必須有二次確認彈窗，按鈕觸控面積保持 48x48px，防誤觸間距 $\ge 8\text{px}$。
