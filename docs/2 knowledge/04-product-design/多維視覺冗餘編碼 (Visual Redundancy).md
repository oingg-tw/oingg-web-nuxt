# 多維視覺冗餘編碼 (Visual Redundancy)

> 多維視覺冗餘編碼（Multi-Dimensional Visual Redundancy）是現代資料視覺化與無障礙工程的核心法則（對應 WCAG 2.2 準則 1.4.1「非單一色彩傳達」）。該法則主張：在金融圖表與數據呈現中，任何關鍵狀態（如漲跌極性、盈虧、多空警示）絕不能單純依賴「色彩」作為唯一資訊管道，而必須同時疊加「幾何形狀」、「文字符號」、「紋理樣式」等多個維度的感知通道，確保色弱、色盲與高齡使用者均能零障礙秒懂。

---

## 1. 金融介面紅綠色彩失效機理

- **色覺缺陷（CVD）現實**：全球男性約有 **8%**、女性約有 0.5% 患有各種類型的色覺障礙（尤以第一色弱紅綠色盲 Protanopia、第二色弱綠黃色盲 Deuteranopia 最為普遍）。
- **混淆線（Confusion Lines）災難**：在色弱使用者的視網膜光學感知中，台股常用的紅（漲）與綠（跌）落在同一混淆光譜上，雙雙坍縮為明度相近的「黃褐色階」，導致多空判讀徹底抵銷失效。
- **全色盲（Achromatopsia）**：完全喪失色相感知，僅能辨識純明度差（Luminance Contrast）。

## 2. 金融組件的多維冗餘編碼實踐清單

```
【傳統不良做法】               【多維視覺冗餘編碼最佳實踐】
純紅色字體: 125.5              紅色 + 顯式正號 + 向上實體箭頭: ▲ +125.5 (+3.2%)
純綠色字體: 121.0              綠色 + 顯式負號 + 向下實體箭頭: ▼ -121.0 (-1.8%)
```

| 金融 UI 元件項目 | 傳統依賴色彩之盲點 | 多維度視覺冗餘改造方案 (幾何 + 符號 + 樣式) |
| :--- | :--- | :--- |
| **報價與漲跌幅標籤** | 僅透過字體變紅或變綠表示。色弱者無法區分漲跌。 | 強制配置**顯式符號前綴**（`+` 或 `-`）以及**方向幾何箭頭**（▲ 上漲 / ▼ 下跌 / ─ 平盤），脫離顏色亦能秒判。 |
| **K 線蠟燭圖 (Candlestick)** | 僅靠紅綠蠟燭實體區分陽線與陰線。 | **幾何化空心陰陽線**：陽線（上漲）採「空心白色燭體（Hollow Body）」，陰線（下跌）採「實心燭體（Solid Body）」，黑白單色下亦完全可辨。 |
| **多條趨勢折線圖 (Line Chart)** | 僅靠 5 種不同顏色區分 5 檔個股走勢。 | **線條樣式分流 + 數據點錨點**：分別指派實線（Solid）、長虛線（Dashed）、點狀線（Dotted），並於數據節點配置圓形、方形、三角形標記。 |
| **折線圖圖例對照 (Legends)** | 圖例放在角落，需反覆比對顏色。 | **末端直接標註（Direct Labeling）**：將股票代號或名稱直接繪製於走勢線的末端右側，免除跳轉尋找圖例的認知摩擦。 |
| **財務健康號誌燈 / 警示框** | 僅靠紅框或黃框標註風險。 | 框線內並列**通用警告圖示**（如帶驚嘆號的三角形 ⚠️）與明確文字提示（如「高槓桿警戒」）。 |

## 3. 跨文化色彩映射 Token 架構

在軟體工程與 Design System 層面，色彩應與語意解耦：

- **業務語意 Token**：`color-semantic-up`（看多/上漲）與 `color-semantic-down`（看空/下跌）。
- **底層主題切換**：
  - **東亞傳統模式**：`up = #DC2626` (紅), `down = #16A34A` (綠)
  - **國際歐美模式**：`up = #16A34A` (綠), `down = #DC2626` (紅)
  - **無障礙模式 (Okabe-Ito / IBM)**：`up = #FE6100` (橘紅), `down = #648FFF` (晴藍)
  - 使用者無論選擇何種主題，幾何符號（▲ / ▼）均固定存在，確保資訊傳達的絕對穩健性（Robustness）。
